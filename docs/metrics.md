# Метрики эксперимента

Какие величины замеряются в каждом запуске `train.py`, как они считаются, где их найти
в ClearML и как их читать. В конце — результаты учителя и метрики, которые добавятся
на шагах 4–6 (KD и статистика по сидам).

Код: `kd/trainer.py` (`train_one_epoch`, `evaluate`), `train.py` (отчёт),
`utils/clearml_utils.py` (`report_split_metrics`, `report_single_values`).

## 1. Определения

Пусть $z \in \mathbb{R}^{100}$ — логиты модели для изображения, $y$ — истинный класс,
$N$ — число примеров в выборке.

| Метрика | Формула | Смысл |
|---|---|---|
| `top1` | $\frac{1}{N}\sum_i [\arg\max_k z_{ik} = y_i]$ | доля верных предсказаний (accuracy), $[0, 1]$ |
| `top5` | $\frac{1}{N}\sum_i [y_i \in \text{top-5}(z_i)]$ | доля примеров, где истинный класс среди 5 самых вероятных |
| `ce` | $\frac{1}{N}\sum_i -\log \operatorname{softmax}(z_i)_{y_i}$ | перекрёстная энтропия по меткам, в натах |
| `loss` | значение целевой функции обучения | для обучения на метках совпадает с `ce` |
| `precision` | $\frac{1}{K}\sum_k \frac{TP_k}{TP_k + FP_k}$ | macro precision: доля верных среди предсказанных классом $k$, среднее по классам |
| `recall` | $\frac{1}{K}\sum_k \frac{TP_k}{TP_k + FN_k}$ | macro recall: доля найденных примеров класса $k$, среднее по классам |

Для `precision`/`recall`: $\hat y_i = \arg\max_k z_{ik}$, $TP_k$ — примеры класса $k$,
предсказанные как $k$; $FP_k$ — примеры других классов, предсказанные как $k$;
$FN_k$ — примеры класса $k$, предсказанные иначе; $K$ — число классов в истинных метках
выборки (на val и test — все 100).

Подробности расчёта:

- Все метрики — **средние по примерам**: значение батча умножается на его размер,
  суммы делятся на общее число примеров. Неполный последний батч на val/test учитывается
  с правильным весом.
- Логиты считаются под `torch.autocast` (fp16 на CUDA), но лосс и метрики — по логитам,
  переведённым во `float32`.
- `top1`/`top5` в отчётах — **доли**, не проценты: `0.7951` = 79.51%.
- Случайный уровень для 100 классов: `top1` = 0.01, `top5` = 0.05, `ce` = $\ln 100 \approx 4.605$.
  Это полезный ориентир для первых эпох и smoke-запусков.
- `precision` и `recall` считаются только на val/test (`evaluate`), по предсказаниям всей
  выборки сразу, а не как среднее по батчам: метрика класса зависит от всех его примеров.
  Усреднение macro — каждый класс с одинаковым весом. Класс, который модель ни разу
  не предсказала, получает precision 0 (как `zero_division=0` в sklearn).
- **Macro recall на val и test совпадает с `top1`.** Обе выборки сбалансированы
  (50 и 100 примеров на класс), а при равных размерах классов среднее recall по классам
  равно общей доле верных ответов. Новую информацию несёт `precision`: она ниже `top1`,
  если модель «сваливает» ошибки в несколько классов-поглотителей, и выше — если ошибки
  распределены по многим классам. `recall` логируется для полноты и как проверка.
- Micro-усреднение не используется: для однометочной классификации micro precision
  и micro recall оба равны `top1`.

## 2. Метрики по эпохам (вкладка Scalars)

Логируются после каждой эпохи, номер итерации = номер эпохи (1…`num_train_epochs`).
Один график — одна метрика, линии (series) — части данных `train` и `val`, поэтому
на графике сразу видно расхождение train и val.

| График | `train` | `val` | Что показывает |
|---|---|---|---|
| `loss` | ✓ | ✓ | целевая функция |
| `ce` | ✓ | ✓ | CE по меткам (компонент лосса) |
| `top1` | ✓ | ✓ | точность |
| `top5` | — | ✓ | top-5 точность |
| `precision` | — | ✓ | macro precision |
| `recall` | — | ✓ | macro recall (на сбалансированном val = `top1`) |
| `lr` | ✓ | — | скорость обучения на конец эпохи |
| `epoch_time` | ✓ | — | длительность эпохи обучения, с |

### Train и val считаются по-разному

| | train | val |
|---|---|---|
| Когда | во время эпохи, параллельно с обучением | после эпохи, на зафиксированных весах |
| Режим модели | `train` (BatchNorm по статистикам батча) | `eval` (BatchNorm по накопленным статистикам) |
| Аугментации | да (кроп + отражение) | нет |
| Веса | меняются от батча к батчу; метрика — среднее за эпоху | одни веса на всю выборку |
| Состав | 45 000 примеров, `drop_last` | все 5 000 примеров |

Поэтому train-метрики — не «точность на обучающей выборке» в строгом смысле, а средняя
точность по ходу эпохи на аугментированных данных. Для оценки переобучения сравнивается
динамика, а не абсолютные значения.

### Прочие замечания

- `lr` — значение после последнего шага эпохи. График пошаговый (warmup + косинус),
  внутри эпохи LR тоже меняется.
- `epoch_time` включает только проход обучения, без оценки на val и сохранения чекпоинта.
  По нему оценивается бюджет сессий Colab.
- Частота оценки на val — `--eval_every` (по умолчанию каждую эпоху). Последняя эпоха
  оценивается всегда.
- При продолжении после обрыва сессии графики продолжаются с той же эпохи, без сдвига.
  Эпохи после последнего чекпоинта пересчитываются и логируются повторно, так что
  в этих эпохах на графике может оказаться по две точки.
- ClearML сам добавляет графики `:monitor:gpu` и `:monitor:machine` (загрузка GPU,
  память, CPU, сеть). Они нужны только для диагностики производительности.

## 3. Итоговые метрики (single values, таблица экспериментов)

После обучения финальная модель — веса после последней эпохи, т.е. в конце
косинусного графика LR — оценивается на val и test. Результат записывается
как single values. Эти значения видны колонками в таблице экспериментов ClearML
и из них собирается статистика по сидам.

| Имя | Значение |
|---|---|
| `test/top1`, `test/top5`, `test/precision`, `test/recall`, `test/ce`, `test/loss` | **основные метрики эксперимента** — финальная модель на test (10 000) |
| `val/top1`, `val/top5`, `val/precision`, `val/recall`, `val/ce`, `val/loss` | финальная модель на val (5 000) |
| `model/n_params` | число обучаемых параметров |
| `model/best_val_top1` | лучшая `val/top1` за всё обучение (справочно) |

**Серия запусков (`--n_runs N > 1`).** Одна задача ClearML обучает модель N раз
из разных начальных состояний (`kd/experiment.py`):
- графики по эпохам — series `train/run<i>` и `val/run<i>`;
- single values `val/<m>`, `test/<m>` — среднее по запускам, `val/<m>_std`, `test/<m>_std` —
  стандартное отклонение (ddof=1); `model/best_val_top1` — среднее;
- артефакт `runs` — таблица: запуск, `model_seed`, все метрики val/test;
- артефакты `summary_run<i>` — итог каждого запуска, по ним пропускаются завершённые
  запуски при продолжении.

При `n_runs=1` series остаются `train`/`val`, `_std` не пишется.

**Почему финальная модель, а не лучшая по val.** Выбор эпохи по максимуму val — это ещё
одна подгонка под шум val. При сравнении многих сидов это вносит смещение, разное
у разных конфигураций. Финальная модель зависит только от сида и гиперпараметров.
`model/best_val_top1` логируется только для контроля: если он заметно выше финального
`val/top1`, рецепт переобучается к концу.

**Test используется только здесь.** Ни выбор эпохи, ни подбор ёмкости ученика, ни подбор
α и T на test не смотрят — для этого есть val.

## 4. Артефакты запуска

| Где | Что |
|---|---|
| ClearML → Artifacts → `summary` | словарь: `arch`, `seed`, `n_params`, все метрики `val`/`test`, `best_val_top1`, все аргументы запуска |
| ClearML → Models → `<task_name>-run0` | веса финальной модели первого запуска (files server ClearML) |
| `<output_dir>/<task_id>/summary.json` | агрегат серии и итоги всех запусков локально / на Google Drive |
| `<output_dir>/<task_id>/run_<i>/model_final.pt` | веса, `model_seed` и аргументы запуска `i` |
| ClearML → Configuration → `Args` | все параметры запуска (по ним задача клонируется) |

Промежуточные чекпоинты в ClearML не попадают (кроме опции `--upload_checkpoint`).

## 6. Метрики дистилляции (шаг 4, план)

Раздел описывает, что будет логироваться после реализации KD-лосса. В коде этого пока нет.

KD-лосс: $\mathcal{L} = \alpha \cdot \mathrm{CE}(y, z_s) + (1-\alpha) \cdot T^2 \cdot
\mathrm{KL}\big(\operatorname{softmax}(z_t/T) \,\|\, \operatorname{softmax}(z_s/T)\big)$.

Целевая функция возвращает компоненты, и они логируются тем же механизмом, что и `ce`:

| График | Значение |
|---|---|
| `loss` | полный KD-лосс $\mathcal{L}$ |
| `ce` | $\mathrm{CE}(y, z_s)$ без веса α |
| `kl` | $\mathrm{KL}(\cdot\|\cdot)$ при температуре $T$ (без множителей $T^2$ и $1-\alpha$) |

На val учитель прогоняется на тех же изображениях, поэтому `kl` на val показывает, насколько
ученик воспроизводит учителя на новых данных, а `ce` — насколько он решает задачу.
По этим кривым и `val/top1` подбираются α и T (шаг 5).

Компоненты логируются **без весов**, чтобы их можно было сравнивать между запусками
с разными α и T. Сумма с весами — это `loss`.

## 7. Сравнение по сидам (шаг 6, план)

Каждая конфигурация («ученик на CE», «ученик с KD») запускается на $n \approx 10\text{–}20$
сидах. Единица наблюдения — `test/top1` одного запуска. Запуски собираются из ClearML
по тегам.

| Величина | Как считается |
|---|---|
| среднее и ст. отклонение `test/top1` по сидам | для каждой конфигурации |
| $\Delta$ — абсолютная разница средних | $\overline{\text{top1}}_{KD} - \overline{\text{top1}}_{CE}$, в п.п. |
| бутстрап-ДИ для $\Delta$ | перевыборка сидов внутри каждой группы, 95% |
| Welch t-test | разница средних без предположения о равных дисперсиях |
| Mann–Whitney U | непараметрическая проверка сдвига распределений |

Также сравниваются ученик и учитель (разница должна быть значимой и заметной по абсолютной
величине — шаг 3). По сидам агрегируются и `test/top5`, `test/precision`, `test/ce`
(`test/recall` равен `test/top1` и отдельно не анализируется).

Разбиение train/val фиксировано (`--split_seed`), а test одинаков для всех запусков.
Разброс между сидами отражает только инициализацию, порядок батчей и аугментации.
