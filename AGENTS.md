# AGENTS.md — договорённости по проекту cifar100-distillation

Файл — источник истины для любого агента/ассистента, работающего в репозитории.
Перед началом работы прочитай его целиком.

## Постановка задачи

1. Обучить модель с ёмким состоянием и известной архитектурой (ResNet-50) до высокой
   точности на CIFAR-100 — это «учитель».
2. Спроектировать значительно меньшую модель (небольшая CNN) — «ученик». Обучить на том же
   датасете, сравнить качество. При необходимости уменьшать ёмкость ученика, пока разница
   с учителем не станет статистически значимой и заметной по абсолютному значению.
3. Реализовать функцию потерь: взвешенная сумма перекрёстной энтропии и меры различия между
   логитами ученика и сглаженными (температура T) логитами учителя (KL-дивергенция).
4. Обучить ученика с этой функцией потерь. По метрикам и отдельным компонентам лосса на
   валидации подобрать веса (α, T), балансирующие копирование учителя и обучение на метках.
   Добиться статистически значимого улучшения относительно ученика, обученного только на
   метках; посчитать абсолютную разницу метрик; оценить значимость по множеству запусков
   с разными сидами. Сделать выводы.

## Принятые решения

- **Отдельный репозиторий** `cifar100-distillation` (github.com/esgon191/cifar100-distillation).
  За основу взят пайплайн из `../airline-sentiment-analysis` (ветка master, остальные ветки
  не нужны) — перенесены ClearML-обвязка, CLI и тест подключения.
- **ClearML** — для фиксации результатов и множественного обучения. Каждый запуск —
  задача ClearML; все параметры запуска идут через argparse → `task.connect(args)`, чтобы
  задачу можно было клонировать с другим `seed`/`alpha`/`T` и ставить в очередь.
  Сервер — app.clear.ml (бесплатный тариф).
- **S3 не используем.** Артефакты/модели — на files server ClearML (`output_uri=True`) или
  локально. В `~/clearml.conf` у пользователя остался `default_output_uri` на S3 —
  в `Task.init` указывать `output_uri` явно, не полагаться на конфиг. Следить за объёмом:
  на бесплатном тарифе хранилище ограничено, тяжёлые чекпоинты (ResNet-50) — только лучший.
- **Вычисления** — бесплатная GPU T4 в Google Colab (clearml-agent / запуск задачи в Colab).
  Локально (macOS) torch не установлен — локально только пишем код и делаем smoke-тесты.
  T4: использовать AMP (fp16), `channels_last`; время сессии Colab ограничено — обучение
  должно уметь продолжаться с чекпоинта, эпохи и число сидов подбирать под бюджет.
- **Учитель обучается с нуля** (без ImageNet-предобучения): ResNet-50, адаптированный под
  32×32 (стем conv3x3 stride 1, без maxpool). Цель ≈ 78–80% top-1.
- **Фреймворк** — чистый PyTorch + torchvision со своим циклом обучения (HF Trainer из
  старого проекта не используем).
- **Разбиение данных**: из 50k train выделяется фиксированный val (5k, стратифицированно,
  фиксированный сид разбиения, не зависящий от сида обучения) — для подбора α, T и ёмкости
  ученика. Test (10k) — только для итоговых метрик.
- **Учитель в KD работает онлайн** на тех же аугментированных батчах, что и ученик
  (а не на заранее посчитанных логитах без аугментаций).
- **KD-лосс**: `α·CE(y, z_s) + (1−α)·T²·KL(softmax(z_t/T) ‖ softmax(z_s/T))`.
  Компоненты (CE, KL) логируются в ClearML отдельно на train и val.
- **Статистика**: N сидов (≈10–20) для «ученик на CE» и «ученик с KD», разница средних
  на test, Welch t-test / Mann–Whitney, бутстрап-ДИ. Агрегация — отдельной задачей,
  собирающей результаты из ClearML по тегам.

## План по шагам

1. Каркас: структура пакета, загрузка CIFAR-100, разбиение, фиксация сидов, цикл обучения,
   логирование в ClearML; smoke-тест.
2. Учитель ResNet-50 с нуля.
3. Ученик: архитектура и подбор ёмкости, бейзлайн на CE.
4. KD-лосс.
5. Подбор α и T на val (сетка через клонирование задач / HyperParameterOptimizer).
6. Множественные запуски с разными сидами и статистический анализ.
7. Выводы и отчёт.

## Структура кода (шаг 1)

- `train.py` — единая точка входа обучения (учитель/ученик, `--arch resnet50|cnn`).
- `kd/data.py` — загрузка CIFAR-100 (pickle `train/test/meta`), стратифицированное
  разбиение train/val, `DeviceLoader`: датасет целиком на GPU в uint8, аугментации
  (RandomCrop 32 pad 4 + HFlip) и нормализация батчево на устройстве — CPU Colab
  не узкое место. Порядок/аугментации эпохи задаются (seed, epoch).
- `kd/models.py` — `resnet50_cifar`, `SimpleCNN` (ёмкость: `--cnn_width`,
  `--cnn_convs_per_stage`).
- `kd/trainer.py` — SGD (nesterov) + warmup/cosine по итерациям, AMP, train/eval,
  чекпоинты. Целевая функция — объект `(logits, targets, teacher_logits) -> (loss,
  компоненты)`; KD-лосс шага 4 реализует тот же интерфейс, учитель передаётся в
  `train_one_epoch`/`evaluate`.
- Метрики в ClearML: график = метрика (`loss`, `ce`, `top1`, …), series = `train`/`val`.
  Итог — single values `test/*`, `val/*` + артефакт `summary`; итоговая метрика —
  финальная модель (конец косинуса), не лучшая по val.
- Чекпоинт `out/<task_id>/group_<i>/checkpoint.pt` (группа запусков; учитель писал в `out/<task_id>/`) каждые `--save_every` эпох, `--resume` по
  умолчанию; в Colab `--output_dir` — на Google Drive (см. «Запуск в Colab»), либо
  `--upload_checkpoint` (артефакт ClearML) + `--continue_task_id`.
- `output_uri` = `Session.get_files_server_host()` (явно, мимо S3 из конфига);
  автологирование `torch.save` выключено; в ClearML грузится только `model_final.pt`.
- Данные: локально `data/cifar_100` (в .gitignore). На воркере/в Colab — ClearML Dataset
  `cifar100` v1.0.0 (проект `cifar100-distillation`, files server, 163 МБ):
  `--dataset_name cifar100`. Зарегистрирован `register_dataset.py` (один раз; S3 из
  конфига обходится через `CLEARML_DEFAULT_OUTPUT_URI`, т.к. `Dataset.create`
  принудительно ставит `output_uri=True`). Скачивание torchvision (если в `--data_dir`
  нет файлов) — запасной путь: сервер CIFAR отдаёт ~90 КБ/с.
- Smoke-тесты: `python -m pytest tests` (venv в `venv/`).
- `--weight_decay_norm_bias` (по умолчанию вкл.) — weight decay и на BN/bias, как в
  классических CIFAR-рецептах; `--no-weight_decay_norm_bias` — только на веса conv/linear.

## Запуск в Colab (решено)

- **Основной путь — ручной запуск** `python train.py ...` из Colab-ноутбука
  (`colab/train_teacher.ipynb`), задача ClearML создаётся `Task.init` внутри скрипта.
  Ключи ClearML — из Colab Secrets через переменные окружения `CLEARML_API_*`
  (наследуются процессом `train.py`), в коде и ноутбуке не хранятся.
- В Colab torch/torchvision не переустанавливаются: ставится `requirements.txt` без них.
- Чекпоинты — на Google Drive: `--output_dir /content/drive/MyDrive/cifar100-distillation/out`,
  каталог запуска `<output_dir>/<task_id>`. После обрыва сессии — тот же набор аргументов
  плюс `--continue_task_id <task_id>`: ClearML продолжает ту же задачу (тот же id → тот же
  каталог → подхватывается `checkpoint.pt`). Проверено smoke-задачей.
- Особенности `init_task`: без `--continue_task_id` всегда новая задача
  (`reuse_last_task_id=False`); при продолжении проверяется, что id совпал (иначе ClearML
  молча создал бы новую задачу и обучение пошло бы с нуля); сдвиг итераций при
  продолжении отключён (`set_initial_iteration(0)`) — метрики репортятся по номеру эпохи.
- clearml-agent в Colab (очередь `colab-t4`, системный Python без venv) — запасной вариант
  для массовых запусков, описан в приложении ноутбука.

## Шаг 2: учитель ResNet-50

- Запуск: `colab/train_teacher.ipynb` → `train.py --arch resnet50 --tags teacher
  --task_name teacher-resnet50-seed0 --num_train_epochs 200 --learning_rate 0.1
  --per_device_train_batch_size 128 --weight_decay 5e-4 --warmup_epochs 1 --save_every 2`
  (nesterov, косинус, AMP, `channels_last` — по умолчанию на CUDA). Без label smoothing:
  учитель со сглаживанием хуже передаёт «тёмные знания».
- Бюджет: ResNet-50 под 32×32 — ≈7.8 GFLOP на изображение (forward+backward), эпоха
  45k примеров ≈3.5·10¹⁴ FLOP. Оценка для T4 (AMP, 6–10 TFLOPS эффективно) — 40–65 с
  на эпоху, 200 эпох ≈2.5–3.5 ч, т.е. 1–2 сессии Colab. Это оценка — уточнить по
  `epoch_time` первых эпох. Локально (Apple M4, MPS, fp32) — ≈140 img/s, ~5 мин/эпоха;
  `channels_last` на MPS падает в backward (баг MPS), поэтому он включается только на CUDA.
- Ориентир: ResNet-50 с этим рецептом на полном train — ≈77–79% top-1; у нас train 45k
  (5k ушло в val), возможна потеря ≈0.5 п.п.

## Шаг 3: ученик и бейзлайн на CE

Подробно — `docs/student.md`.

- **Учитель обучен:** test top1 0.7951, задача ClearML `60b07234…`.
- **Многократное обучение — `kd/experiment.py`:**
  - абстрактный `Experiment(args, model_cls, model_kwargs, loaders, device, run_dir, task)`,
    метод `run(n_runs, init_seed)`;
  - подкласс задаёт `build_objective()` и `teacher()`; KD шага 4 — ещё один подкласс;
  - `--init_seed` порождает сиды начальных весов (`SeedSequence.spawn`, префикс
    стабилен при росте `--n_runs`);
  - всё остальное случайное — от глобального `--seed`, общего для серии;
  - `--parallel_runs K`: K запусков обучаются одной группой на общих батчах
    (`kd/stacked.py::stack_models`). Для `SimpleCNN` — `GroupedCNN`: K моделей как одна
    сеть на grouped conv, с `channels_last` и AMP. `StackedModel` (`vmap`) — для прочих
    архитектур; на T4 он медленнее одной модели с `channels_last` (vmap его не
    поддерживает), поэтому с K > 1 на CUDA запрещён. Целевая функция
    возвращает лосс каждой модели `[K]`, а `train_one_epoch`/`evaluate` — список метрик
    по моделям; одиночная модель — частный случай K=1. Эквивалентность последовательному
    обучению проверена тестами. Оговорка: GradScaler общий на группу. K выбирается
    по `scripts/bench_parallel.py`;
  - каждая метрика и компонента лосса замеряется на **финальной** модели: отдельный
    eval-проход по train (без аугментаций), val и test;
  - **всё сохраняется на диск** в `<output_dir>/<task_id>/`, в Colab —
    `/content/drive/MyDrive/cifar100-distillation/out/<task_id>/`:
    - на запуск — `run_<i>/final.json`, `history.csv`, `logits.npz` (val/test, fp16),
      `model_final.pt`;
    - на серию — `series.json`, `final_metrics.csv`, `test_metrics.csv`, `history.csv`;
    - чекпоинт группы `group_<i>/checkpoint.pt` удаляется по завершении группы;
    - запуск с `final.json` пропускается; в конце `verify_series_files` проверяет, что все
      файлы на месте;
  - одна серия — одна задача ClearML. Во время обучения scalars не пишутся, только
    консоль. В конце из файлов отправляются: кривые (среднее по запускам, series
    `train`/`val`), single values (среднее и `_std`), артефакты `test_metrics` (главный:
    test финальных моделей, строка = запуск), `final_metrics`, `history`, `series`,
    веса `run_0`. Повторить отправку без обучения — `--report_only --continue_task_id`;
  - таблицы — CSV, не parquet: `pyarrow` не в зависимостях;
  - на шаге 4 логиты учителя одинаковы для всей группы и всей серии (одни и те же
    аугментированные батчи) — их можно посчитать один раз.
- **Подбор ёмкости — ClearML `HyperParameterOptimizer` + `GridSearch`**
  (`scripts/capacity_search.py`):
  - сетка `cnn_width` {16, 32, 48, 64} × `cnn_convs_per_stage` {1, 2}, каждая модель
    обучается один раз, 100 эпох;
  - цель — последнее `top1/val`;
  - задачи исполняет `colab/agent.ipynb` (очередь `colab-t4`, создаётся самим агентом
    флагом `--create-queue`), код берётся из GitHub, поэтому перед запуском нужен push;
    контроллер проверяет, что очередь существует; контроллер запускается через
    `optimizer.start()` — `start_locally()` исполняет задачи сетки на машине контроллера
    (на Mac падало на пути Drive `/content`);
  - предупреждение «Could not find requested metric ('top1', 'val') report on base task» —
    норма: базовая задача — черновик, она не обучалась;
  - теги базовой задачи передаются строкой-списком `"['a', 'b']"`: агент разбирает
    `nargs="*"` через yaml.
- **Критерий выбора** (только val): отставание от учителя ≥ 10 п.п., точность ещё растёт
  с ёмкостью, при прочих равных — меньшая модель.
- **Бейзлайн:** выбранная модель, `--n_runs 100 --parallel_runs K`, теги
  `student-ce baseline` (`colab/train_students.ipynb`).
- **Ветка `parallel-runs`:** параллельные серии и новый формат данных. В `master`
  попадают только после завершения сетки ёмкости: новый цикл не пишет поэпоховые
  scalars `val`, а по ним считается цель GridSearch.
- **Значимость разницы ученик/учитель не считаем** — по решению пользователя.
